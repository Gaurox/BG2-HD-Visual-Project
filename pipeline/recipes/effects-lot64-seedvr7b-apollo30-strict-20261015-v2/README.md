# Lot64 — strict-v2, 7B x4 / NEAREST / Apollo30, cycles natifs

- Plan autorisé : `effects/batches/lot64-seedvr7b-apollo30-strict-20261015-v2/batch.json` ; sources du lot proposé64 ; 4097 records BAM, 226 cycles, 4961 slots bruts alternatifs. Ne pas sommer leurs durées comme un seul effet.
- Spatial conservé depuis `effects-lot64-seedvr7b-apollo30-20261015-v1/spatial.py` : workflow 7B approuvé, LAB x4, alpha natif NEAREST ; attente ComfyUI0.2s. Aucune nouvelle inférence spatiale pour strict-v2. `reused-results.json` conserve aussi les26 premiers résultats temporels dont toutes les images RGB/RGBA étaient déjà distinctes ; nouvelle vérification indépendante stricte.
- `temporal.py` : chaque cycle/direction séparément ; interprétation des rôles VVC introduction/durée/fin, seule la phase de durée boucle. Références 1-based, normalisation des anciens contrôleurs ; [VVC/IESDP](https://gibberlings3.github.io/iesdp/file_formats/ie_formats/vvc_v1.htm), [interprétation des phases/GemRB](https://github.com/gemrb/gemrb/blob/master/gemrb/core/ScriptedAnimation.cpp). Toute consommation à la fois ponctuelle et bouclée conserve deux profils ; aucun mélange de directions lors d'Apollo.
- Retiming strict : enlever toutes les poses natives identiques dans chaque cycle, même non consécutives, et les marges temporelles entièrement noires ; jamais dédupliquer entre cycles/directions distincts. `S` slots natifs15FPS => `2*S` phases30FPS, durée exactement `S/15`. Ponctuel : `K` poses distinctes, inputFPS=`30*(K-1)/(2*S-1)`, dernière pose retenue sur dernière phase, sans demi-frame finale doublée. Boucle : inputFPS=`30*K/(2*S)` ; interpolation dernière→première, endpoint de fermeture non émis deux fois.
- Contrôle purement transparent/static natif : conserver contenu et durée, aucune animation artificielle. Cas SPCOMEXP/cycle1 : un slot invisible, deux phases temporelles à30FPS ; ne pas qualifier ces pixels noirs de doublon animé.
- RGB : Apollo8 RGB seul, alpha = couverture native x4 interpolée temporellement, Gaussian RGB1.2px x4, feather intérieur12px x4, prémultiplication une fois. Pas d'expansion spatiale de l'alpha.
- Géométrie : BAM porteur avec padding transparent uniquement, palette/indices visibles/centres monde/lookup/cycles natifs strictement conservés. Toutes les variantes partagent le porteur nécessaire ; dimensions visibles et durée natives inchangées. Aucune installation par ces scripts.
- Packs mono-BAM v2 : table native par cycle + table30FPS. Le format impose une largeur uniforme des tables : les queues au-delà des `2*S` phases réelles sont des entrées inaccessibles, sans durée ajoutée ni image présentée en plus. `actual_phase_counts_by_cycle` et contrats natifs explicitent les frontières. Les profils alternatifs restent dans le run ; le choix par consommateur doit être pris en compte lors d'une installation ultérieure, jamais confondu avec la QA/installation courante.
- `verify.py` : décodage indépendant des BAM source/porteur, pixels monde, palette, cycles, durées rationnelles, SHA des images/pack, x4 exact, modèle7B, alpha borné ; rejet de tout doublon RGB/RGBA dans un cycle animé, consécutif ou non, raccord de boucle compris. Exception uniquement pour contenu natif constant/invisible explicitement recensé. Contrats par séquence/slot/dimensions/phase/backing dans `contracts/*.tsv` ; probe natif `iee_effect_animation_x4_registry_tests.exe <pack> <contrats>`.
- `review.py` : HTML64 cases, chaque cycle/profil sélectionnable ; WebP animé lossless, RGB prémultiplié sur noir, vignettes NEAREST. Timestamps WebP33/34ms par arrondi cumulatif ; quatre vidéos CFR30 exact,12s, H264CRF15 pour lecture pratique (dérivés, pas assets de production). Ponctuels rejoués avec pause0.5s ; boucles sans pause. Aucune taille ingame déduite de la taille des cases.
- `full_posters.py` : une frame RGB x4 sans réduction par effet, accessible depuis chaque case ; aucune double application de l'alpha. `review/full-posters.json` lie les64 PNG aux phases de production.
- Sprites/AA, renderer installé, cartes, effets installés, QA et release préservés ; `installation-preserved-reference.json` lie les fichiers existants au reçu renderer précédent.
